# 学习指南

按这个顺序读。每一步都先在页面上点一下，再打开对应文件，看这次点击变成了哪一行代码。

不要从头到尾把所有文件读完。读不懂的语法先放着，把它和页面上的行为对上就够了。

## 0. 确认它是活的

用 `ada / learn123` 登录。你应该能看到两门课、一篇置顶笔记，以及一个已经逾期的任务。

## 1. 从前端的一个按钮走到数据库

选「新建课程」。

1. 打开 `web/src/views/CourseListView.vue`，找到 `save`。它调用 `createCourse`。
2. 打开 `web/src/api/learnlab.ts`，看到请求发往 `POST /api/courses`。
3. 打开 `web/src/api/http.ts`。请求发出前，拦截器会带上 `Authorization: Bearer ...`。失败时把后端的 `message` 变成页面上的提示。
4. 打开 `server/.../course/CourseController.java`。`@Valid` 会先按 `CourseRequest` 上的注解检查标题。
5. 打开 `CourseService.java`。这里才决定「课属于当前登录的人」。
6. `CourseRepository` 没有手写 SQL。保存 `Course` 对象时，Hibernate 会生成 `insert`。

改一处就能验证你跟对了：把 `CourseRequest` 的标题长度改成最多 5 个字，重启后端，再新建一门名字很长的课，看页面上的报错是不是变了。改完改回去。

## 2. Vue 这边先看懂四样东西

| 概念 | 文件 | 你要认出什么 |
| --- | --- | --- |
| 单文件组件 | `web/src/views/DashboardView.vue` | `script`、`template`、页面上的数据来自 `ref` |
| 路由 | `web/src/router/index.ts` | `/courses/:id` 这种路径，以及没登录为什么进不去 |
| 状态 | `web/src/stores/auth.ts` | token 放在 Pinia，同时抄进 localStorage，刷新页面还在 |
| 复用逻辑 | `web/src/composables/useAsync.ts` | 加载中和报错不用每个页面各写一遍 |

`PageHeader.vue` 是最小的组件例子：父页面传入 `title`，中间的按钮通过插槽塞进去。

路由守卫在 `router/index.ts` 底部。`meta.requiresAuth` 不是自动生效的，是 `beforeEach` 里自己判断的。管理员页面多看了一眼 `requiresAdmin`。

练习：在侧栏加一个「关于」链接，新建 `AboutView.vue`，路由挂到 `/about`。不调接口也行，先让页面出现。

## 3. 后端的分层不要跳着看

以笔记为例，四个类型各干一件事：

- `NoteController`：HTTP。路径、状态码、把 JSON 接进来。
- `NoteRequest` / `NoteDetail`：进出接口的数据结构。不要直接把实体 `Note` 返回给前端，否则密码哈希这类字段以后会不小心漏出去。用户实体已经按这个规矩做成了 `UserView`。
- `NoteService`：业务。是不是你的笔记、标签要不要新建、删笔记时文件也要删。
- `NoteRepository`：查询。复杂条件写在 `@Query` 里，简单的保存用接口自带的 `save`。

`open-in-view` 在 `application.yml` 里关了。意思是：控制器返回之后，不能再临时去数据库补数据。所以标签、附件都在 Service 的事务里组装进 `NoteDetail`。如果以后你在控制器里访问 `note.getTags()` 却看到懒加载错误，就是这条规则在起作用。

## 4. 数据库

先读 [数据库.md](数据库.md)，再打开 H2 控制台，跑：

```sql
select id, title, owner_id from course;

select n.title, t.name
from note n
join note_tag nt on nt.note_id = n.id
join tag t on t.id = nt.tag_id;
```

第二句就是多对多：笔记和标签不直接互相塞数组，中间有一张 `note_tag`。

然后在页面上新建一个标签，再查 `tag` 表。标签列表接口有缓存，看 `TagService` 上的 `@Cacheable`。新建标签时 `@CacheEvict` 会把缓存清掉，否则你要等十分钟才看得到新标签。

## 5. 登录是怎么站住的

注册和登录在 `AuthService`。密码不会明文入库，`PasswordEncoder` 做的是 BCrypt。

登录成功后 `JwtService` 签发一段 token。前端把它放进请求头。之后每个请求到 `SecurityConfig`：

- 注册、登录、健康检查、Swagger、H2 控制台放行
- `/api/admin/**` 要 `ADMIN`
- 其他接口必须登录

`DbJwtAuthenticationConverter` 不轻信 token 里的角色。它按用户名再查一次库，所以管理员把账号停用后，旧 token 马上失效。这是 JWT 和服务器会话的差别：票据本身改不了，要失效就得每次核对账号状态。

练习：在 `SecurityConfig` 里把 `GET /api/tags` 改成不用登录也能访问。用浏览器隐身窗口直接打开 `http://localhost:8080/api/tags` 看结果。然后改回去，想一下标签列表为什么仍然应该登录后才能看。

## 6. 其他横切的东西

这些不负责某一种业务，请求路过时它们会插手。

- 参数不合法、笔记不存在、程序抛了意外：`GlobalExceptionHandler`。前端永远拿到 `{ success, code, message, fields }`。
- 每次进控制器打一条耗时日志：`ApiLogAspect`。看后端控制台里的 `API ... 完成，用时`。
- 每天 8 点统计逾期任务：`OverdueScanJob`。页面上的逾期数字不靠这个定时任务，仪表盘自己查。定时任务是为了让你看到 `@Scheduled` 长什么样。
- 上传文件：`FileStorage` 把文件放进 `server/uploads`，数据库只存文件名。下载时带上登录身份，不能靠猜一个地址把别人的文件下走。

## 7. 测试在保护哪条路
