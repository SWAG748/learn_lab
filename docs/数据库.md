# 数据库

表结构只有一份：`server/src/main/resources/db/migration/V1__init_schema.sql`。

应用启动时 Flyway 执行还没跑过的脚本，并在 `flyway_schema_history` 里记账。已经跑过的脚本不要改内容，否则校验会失败。要改表就新增 `V2__某某.sql`。

Hibernate 的 `ddl-auto` 设成了 `none`。它不会偷偷帮你建表或改表。表以 SQL 文件为准。

## 用哪一个库

| 配置 | 什么时候用 | 数据在哪 |
| --- | --- | --- |
| `dev`（默认） | 平时学习 | `server/data/` 下的 H2 文件 |
| `mysql` | 想用真实的 MySQL | `docker compose up -d` 起来的库 |
| `test` | `mvn test` | 内存里的 H2，测完就丢 |

H2 的连接串带了 `MODE=MySQL`，这样同一份建表 SQL 可以给两边用。所以脚本里没有 `ENGINE=InnoDB` 这种只有 MySQL 认识的写法。

## 表和关系

```text
app_user
   │
   ├── course            一个用户有多门课
   │     ├── note        一门课有多篇笔记
   │     │     ├── note_tag ── tag     笔记和标签多对多
   │     │     ├── note_comment
   │     │     └── attachment
   │     └── study_task  任务可以挂到课上，也可以先不挂
   └── study_task.assignee_id
```

- `app_user` 不叫 `user`，`note_comment` 不叫 `comment`。这两个词在 SQL 里容易撞上保留字。
- `password_hash` 存的是 BCrypt 结果，不是密码原文。
- `note_tag` 的主键是 `(note_id, tag_id)`，同一篇笔记不能把同一个标签挂两次。
- 删除笔记时，数据库用 `on delete cascade` 把评论、附件记录和标签关系一起删掉。磁盘上的文件要靠 `NoteService` 另外删，数据库不会去删文件夹。
- 删除课程不会级联。服务层发现下面还有笔记或任务，就返回冲突，让你先清内容。这样你能看见外键不是只能写成级联。

## 索引

这些索引对应页面上的查法：

- `idx_course_owner`：列出「我的课程」
- `idx_note_course`、`idx_note_author`：某门课的笔记、某人的笔记
- `idx_task_assignee_status`：任务板按人和状态过滤
- `idx_comment_note`、`idx_attachment_note`：打开一篇笔记时带出评论和附件

索引加快的是查找。写入时数据库还要维护索引，所以不是列越多越好。这里只给真的会拿来筛选的列加了。

## 在控制台里自己看

启动后端后打开 <http://localhost:8080/h2-console>。

JDBC URL 复制 `application-dev.yml` 里的 `spring.datasource.url`。用户名 `sa`，密码空。

可以试这几句：

```sql
select username, role, enabled from app_user;

select c.title, u.username
from course c
join app_user u on u.id = c.owner_id;

select n.title, t.name
from note n
join note_tag nt on nt.note_id = n.id
join tag t on t.id = nt.tag_id;
```

在页面上把 ada 停用，再查 `app_user.enabled`，应该变成 false。然后用 ada 登录，请求会被拒绝。这就是「表里的一列」和「接口行为」连在一起。

## 和 Java 类怎么对上

`Course.java` 上的 `@Table(name = "course")`、`@JoinColumn(name = "owner_id")` 必须和 SQL 里的表名、列名一致。对不上的话，启动未必报错（因为没有开 `validate`），但一保存就会在运行时报 SQL 错误。

如果想让启动时就核对一遍，可以把 `application.yml` 里的 `ddl-auto` 临时改成 `validate`。对不上时，日志会告诉你期望的列和实际的列。H2 和 MySQL 对布尔、时间类型的叫法不完全一样，`validate` 有时会为这种差别报错，所以项目默认没有开它。
